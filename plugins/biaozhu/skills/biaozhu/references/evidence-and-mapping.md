# 证据与页面映射规范

在提取 PRD 和匹配设计之前读取。按项目现有存储形式保存下列逻辑信息；字段名可以适配，来源、定位及状态不可丢失。

## 1. 登记资料

为每项来源分配稳定 sourceId，并保存：

- 类型：PRD 文字、PRD 截图、设计画板、原型交互、用户修订；代码或运行页面只作为实现观察。
- 原文件路径或用户提供的地址、标题、版本标识、读取时间及版本是否确定。无版本写“未标明”，不补造。
- 实际读取的章节、页码、画板和状态；不可访问或未读取范围另列，不能当作不存在。
- 可回查定位：文档章节＋段落／条目；PDF 页码；图片文件＋图号＋区域；设计文件＋画板／节点 ID；原型页面＋交互连接。
- 已读取内容的短摘录或精确转述；保留用户可回查的原文位置。用户修订记录实际陈述和确认对象，不构造引用。

PRD 包含图片时必须查看与当前条目相关的页面截图。OCR 仅用于定位文字，关键数字、单位、星号、占位文本、禁用样式和连线需对照图像核实。无法辨认时写“截图不清，待确认”；无法渲染图片时明确哪些视觉信息未核查。

截图中的星号可以支持“显示必填标记”，不能单独证明空值会被拦截或后端执行了必填校验。区分资料定义、界面标识和已验证行为。

同一资料的新旧版本分别登记。用户明确指定的版本或明确“替代”说明决定当前基线；若同一基线内部存在冲突，仍须保留冲突。

## 2. 提取原子需求

按页面、标签、状态和控件拆分 PRD。保留原需求 ID；无 ID 时生成稳定内部条目编号并关联原段落。每条只陈述证据直接支持的内容，例如：

- 页面展示什么字段、说明或状态；
- 用户执行什么操作、结果是什么；
- 什么条件、权限、数值或格式限制；
- 从哪个触发点到哪个页面或状态，携带哪些参数。

一个“保存”按钮名只能支持它的可见名称。只有明确的 PRD 或原型交互才支持提交、成功消息、自动关闭或页面跳转。未写字段长度不能补成常见的 50、100、255 字符；未见原型连线也不能据此写“无跳转”。

跨页面公共规则只应用到原文明确声明的范围，不把局部字段限制传播到所有同名字段。

## 3. 建立双向映射

映射链为：PRD 条目／截图区域 → 设计页面／画板 → 标签与状态 → 控件节点／区域 → 标注编号。

先建立页面清单，再建立控件对应。页面匹配参考标题、导航上下文、独特字段组合、布局区域和版本；记录匹配理由。仅一个相同词语、类似坐标或相似图标不足以证明对应。

分别记录目标定位和需求关联，不能合并为一个互斥状态：

- targetState：已定位（明确唯一目标）、待定位（多个候选或上下文不足）、待复核（版本变化后不再可靠）。
- requirementRelation：已关联、关联待确认、设计未找到（PRD 有条目，已检查设计中无目标）、PRD 未说明（设计有目标，PRD 缺业务说明）。

一个控件可以同时“已定位＋PRD 未说明”；两个同名控件各自已定位，也不意味着某条 PRD 需求可以同时关联它们。设计未找到要同时记录检查范围，不能把未访问画板算成缺失。功能、限制、跳转的字段证据再独立判断，不能用定位状态代替。

标签组、嵌套页签、弹窗和业务状态使用稳定 key 描述上下文，不能用显示序号代替。公共控件仍受页面和父级作用域约束。重复表格行若需要逐实例气泡，使用稳定行 key 定位；同类需求可复用，显示实例不可因排序错绑或在同屏共用相同气泡编号。

截图锚点记录原图尺寸、截图版本和归一化区域 `[x, y, width, height]`（相对于内容图的 0–1 坐标），而非浏览器窗口像素。设计节点用文件／画板／节点 ID。DOM 锚点使用稳定属性且限定页面和作用域。截图换版不能只复用旧坐标。

## 4. 按说明字段记录证据

标注记录保留 id、page、target、scope、category、summary、details、limitations、navigation，以及映射状态、来源、修订和生命周期信息。说明字段各自携带 text、state、evidenceRefs；一条标注可以同时包含有依据和未说明的字段，不能用一条总状态掩盖差异。

字段状态使用：

| 状态 | 使用条件 | 右侧展示 |
| --- | --- | --- |
| 有依据 | PRD 或用户明确修订直接支持，且当前资料不存在冲突 | 说明＋来源 |
| 设计可见 | 设计中可直接观察的文字、状态或原型明确交互 | 设计可见／原型定义＋来源，不当作生产事实 |
| 未说明 | 已检查资料没有定义 | “PRD／设计未说明，待补充” |
| 冲突待确认 | 来源存在互不一致的定义 | 分别列出说法与来源，不选一项覆盖另一项 |
| 待复核 | 来源换版、图像不清或旧确认已不可靠 | 待复核原因和受影响来源 |

“用户已确认”是另外记录的复核事实：谁／哪条实际指令确认了哪些字段及哪个版本。AI 的把握程度、模型置信度或数量评分不能代替证据和用户确认。不需要用户逐条确认有直接依据且对应明确的标注。

示例（虚构资料，仅展示结构；不得作为真实业务依据）：

```json
{
  "id": "A-001",
  "page": {"key": "settings", "name": "系统配置", "route": null},
  "scope": {"tabs": {"settings-tabs": "basic"}, "state": "default"},
  "target": {
    "name": "名称",
    "type": "input",
    "anchor": {"kind": "design-node", "sourceId": "S-DESIGN-01", "nodeId": "basic-name"}
  },
  "mapping": {"targetState": "已定位", "requirementRelation": "已关联", "requirementIds": ["R-012"], "reason": "基本设置画板内唯一名称输入框"},
  "category": ["内容", "限制"],
  "summary": {
    "text": "名称输入框",
    "state": "设计可见",
    "evidenceRefs": [{"sourceId": "S-DESIGN-01", "locator": "基本设置/basic-name", "supports": "标签为名称"}]
  },
  "details": {"text": "用途未说明", "state": "未说明", "evidenceRefs": []},
  "limitations": {
    "text": "最多 20 个字符",
    "state": "有依据",
    "evidenceRefs": [{"sourceId": "S-PRD-01", "locator": "2.1 基本设置/R-012", "supports": "名称最多20个字符"}]
  },
  "navigation": {"text": "跳转未说明", "state": "未说明", "evidenceRefs": []},
  "lifecycle": "active",
  "review": {"state": "未人工确认"},
  "revisions": []
}
```

route 未知时保持未知；设计画板无需具有真实网站路由。evidenceRefs 中的 sourceId 必须存在于项目来源清单。冲突字段需携带各方摘录和来源；缺失项记录已检查范围。

## 5. 编辑、更新与检查

人工编辑必须保留旧版本及原始证据；编辑内容加“用户修订”来源。仅保存文字不等于用户明确解决了关联冲突。确实给出解决指令时记录其作用字段和版本。

自动更新与人工覆盖分别保存；新资料影响已编辑字段时展示差异或标待复核，不能静默抹掉用户内容，也不能继续声称编辑后的文字是原 PRD 原文。

生成前逐字段检查：有依据／设计可见的字段都指向真实读过、能支持该说法的出处；冲突两边均可追溯；未说明未被填成无条件结论；映射与证据状态分开。来源链接只能证明可访问，不能证明内容支持，必须实际核读。
