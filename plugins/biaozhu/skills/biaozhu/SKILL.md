# 标注

以 PRD 和原型／设计稿为本次标注的资料基线。逐条把需求说明对应到具体页面、状态和控件，再沿用编号气泡、右侧可编辑详情和标签隔离的展示方式。AI 负责提取、比对和组织已有信息，不代替用户决定业务规则。

## 输入与启动

用户通常提供两类资料：

- PRD：文档文件、可访问地址，或 PRD 中的文字／页面截图；截图可作为 PRD 输入，不强制要求另有文字版。
- 原型／设计稿：可访问地址及相关页面、画板或节点；访问受限时可使用用户提供的导出页面、截图或原型文件。

版本、标注范围、目标项目、已有标注和用户明确修订是补充信息。从当前任务已给资料中提取，不重复索要。默认覆盖所给资料中本期相关的全部页面、标签和状态，不扩展到链接所在的整个工作区。

启动时登记资料版本、已读范围和访问状态，并简述识别到的范围。缺一类资料时可整理已取得的部分，集中说明缺口；不得用通用产品知识或旧聊天自动补齐。调用本技能更新技能本身不要求用户提交一份业务 PRD。

## 执行顺序

1. 读取 [证据与页面映射规范](references/evidence-and-mapping.md)。登记来源，提取 PRD 中可核实的条目；同时读取关联截图，而非仅提取文字。
2. 打开原型／设计稿，对照页面名称、布局、字段组合、业务状态、标签和版本建立页面及控件映射。保留未匹配项和候选关系，不因同名就强行绑定。
3. 按字段记录来源和状态：内容、功能、限制、跳转分别判断。映射明确且证据充分的条目直接继续；仅把冲突、缺失和不确定对应关系交给用户确认，不要求逐条批准已充分支持的标注。
4. 读取 [展示与验收规范](references/display-and-verification.md)，选择下面合适的呈现方式，实现或更新标注。证据不明但控件位置明确时，可显示“待确认／未说明”的气泡；位置不明时不能随意贴标。
5. 逐页检查标注是否贴对目标、说明是否有对应证据、交互是否保持、编辑是否保存。报告已完成范围和未解决项，不把已生成等同于已确认。

新项目无需先重建业务系统。仅在有目标项目源码或可编辑原型时检查技术栈并接入；代码可用于定位和发现实现差异，不成为本次业务定义的替代来源。

## 资料和内容判断

- 用户对本次资料的明确修订可成为补充依据，记录具体确认内容及涉及版本。普通历史聊天只作查找线索。
- PRD 描述业务意图；原型／设计稿提供控件位置、文案、可见状态与明确绘制的交互。原型连线只能证明该原型定义了什么，不能证明生产功能已实现。
- PRD 文字、PRD 截图与设计不一致时并列展示出处，标记“冲突待确认”；没有明确版本替代关系时，不按文件时间或个人判断静默选一方。
- 每一项具体说法都要有可回查的出处。仅写“来自 PRD”“AI 识别”或一个整份文档链接不够。
- “资料未说明限制／跳转”不等于“无限制／无跳转”。数字、权限、必填、默认值、失败行为及跳转参数不允许凭按钮名、常见设计或模糊截图推断。
- 页面或目标映射有歧义时列出候选和原因；未定位的需求进入对应页面的待定位列表，无页面归属的进入独立资料问题清单。
- 目标设计出现、PRD 未解释的控件仍可编号，正文只写可观察事实与缺口。PRD 提及但设计缺失的控件记录为“设计未找到”，不能创造控件填补。

## 呈现方式

- **可编辑项目／原型**：在用户指定目标上集成标注层，保留原布局及业务操作。正式提交到第三方设计文件须在用户授权范围内进行。
- **只读设计或图片**：使用实际取得的原画板导出、页面截图制作本地交互标注预览，气泡叠加在原图位置，右侧显示可编辑详情。明确标识“标注预览”；页面／标签切换对应不同画板或状态图，不虚构可用表单或原系统业务交互。
- **可访问在线原型**：优先用现有能力读取。仅在工具支持且获授权时使用覆盖层；不承诺能够注入跨域 iframe、访问受保护画布或永久修改第三方服务。受限时改用可取得的原始导出；无法取得则报告对应范围阻塞。

仅提供说明文档不算完成页面标注；资料清单、映射和问题记录是辅助产物。用户只要求审查或方案时，交付相应结果，不自动修改目标页面。

## 编号、编辑与增量更新

- 每个目标使用稳定的 `A-001` 式编号。排序、刷新、页签切换或文案修改不重排；不同标签中的不同语义控件不能共号。
- 区分标注编号、PRD 条目编号、来源编号。更新时复用已有标注编号及可验证映射，保留人工编辑。
- 页面右侧直接编辑和保存标注；人工改写记录为用户修订，保留原证据。编辑文字不自动证明它来自 PRD，也不自动消除冲突。
- PRD、画板或截图版本变化时，只重核受影响项。过期来源和锚点标为“待复核”，不能沿用原确认状态强行贴回新图。
- 暂时不可见、无法访问或新版暂未匹配的目标不等于已删除。明确移除后才标为“已废弃”，编号不复用。
- 本地保存默认采用项目级标注配置和浏览器本地覆盖数据，或复用已有后端；说明实际保存范围。失败时保留编辑草稿，刷新后验证已保存内容。

## 验证与交付

执行展示规范的证据和交互检查，保留页面覆盖及字段证据检查结果。核对 PRD 所列页面与设计页面两侧，不能只计算已打开页面的覆盖率。

交付包含：实际使用的资料及版本、页面／状态覆盖、已定位控件数、带充分证据的说明数、冲突／缺失／待定位项、标注预览入口或项目接入位置、保存范围、已执行验证和未验证原因。区分“有气泡”“有证据”“用户已确认”。

访问、版本或映射问题只暂停受影响部分。无法取得两类核心资料时，交付已整理的事实和明确缺口，不宣称完成联合标注。标注工作不授权提交真实业务表单、修改业务规则或部署生产环境。
