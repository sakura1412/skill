# 标注

直接在现有页面中实现交互式标注层。不要把 Markdown、表格或独立说明文档作为主要交付物；用户应当在原页面上看到编号气泡，点击后查看和编辑详细说明，并在页面右侧看到已打开的标注列表。

标注内容同时依据：

- 当前任务中可用的历史对话、已确认需求、术语和业务规则；
- 仓库内页面当前呈现的内容、交互、校验、权限和路由实现。

历史对话代表产品意图，页面和代码代表当前实现。两者不一致时，在标注中明确写“待确认”并说明差异，不要自行补造规则。无法访问其他 Codex 任务的历史时，只使用当前可用上下文和项目资料。

## 必须实现的效果

1. 覆盖项目中每个可访问页面、路由和主要页面状态，不只处理当前打开的页面。参数化页面可复用同一套标注，但不同业务状态下出现的控件也应覆盖。
2. 页面上的每个按钮、输入框、文本域、选择器、复选框、单选框、开关、日期控件、上传控件、标签页、菜单项、可点击链接、图标按钮及其他可操作元素，都必须有独立编号气泡。不可用、隐藏后出现或条件渲染的控件也要在其实际出现时显示对应标注。
3. 对页面级的重要内容区、状态区或提示信息增加必要的内容标注；不要用一个笼统标注代替多个可交互控件的独立标注。
4. 气泡只显示稳定编号，例如 `A-001`。气泡放在目标控件附近，并用短连接线或明确的贴靠关系指向目标，不能遮住控件文字、输入内容或主要操作区域。
5. 点击气泡后显示该编号的完整详情，并把它加入右侧标注栏。右侧栏允许同时列出多个已经打开的标注，按照打开顺序或页面顺序稳定排列；再次点击、关闭按钮或“清空”操作可移除右侧条目，但不删除标注数据。
6. 右侧栏中的标注正文可以直接编辑并保存。刷新页面和再次进入该页面后修改仍然存在。优先接入项目已有的数据层；没有后端时使用项目内明确的标注配置加开发态本地存储，并说明其保存范围。
7. 标注模式应有清晰的开启/关闭入口。关闭后页面恢复原有视觉与交互，不残留占位或布局偏移。除非用户明确要求，标注功能默认只在开发、演示或指定环境启用，不影响正式业务用户。
8. 标签页必须始终可以正常点击和键盘切换。切换标签后，只显示当前激活标签及页面公共区域的气泡和右侧详情；不得同时显示其他标签面板的标注。标签本身可以有气泡，但气泡不能覆盖标签的主要点击区域。

## 每条标注的内容

每个气泡对应一条结构化记录，至少包含：

- `id`：全项目唯一且稳定的编号；
- `page`：页面名称和实际路由；
- `target`：控件名称、控件类型和稳定定位方式；
- `scope`：标注所属的页面公共区域或标签页标识；标签页内标注必须记录稳定的标签 key/id，不能只记录标签显示文字；
- `category`：内容、功能、限制或跳转；允许同一控件的详情包含多个小节；
- `summary`：一句话说明该控件是什么；
- `details`：具体说明操作结果、输入或选择含义、状态变化以及与其他区域的关系；
- `limitations`：必填、格式、范围、权限、禁用条件、错误状态、空状态或其他真实限制；
- `navigation`：触发方式、目标页面或外链、携带参数和返回路径；不发生跳转时明确写“无跳转”；
- `status`：已确认、待确认或已废弃；
- `evidence`：来源是页面实现、当前历史需求，或两者均有。

右侧详情优先按“编号与控件名、功能说明、限制、跳转、状态/依据”展示。没有限制或跳转时明确显示“无已知限制”或“无跳转”，避免空白造成歧义，但不能把未核实信息写成已确认事实。

## 实现方法

先识别框架、入口、路由、组件体系、样式方案、状态管理和现有测试，再选择与项目一致的实现。优先复用现有 UI 组件和设计变量。

- 在 React/Vue/Svelte 等组件项目中，建立可复用的标注层、气泡组件、右侧栏和标注数据模块，并在页面或公共布局中接入。
- 在静态 HTML 项目中，使用独立的标注脚本和样式文件初始化覆盖层。
- 优先给目标元素增加稳定的 `data-annotation-id`（或项目等价属性），不要依赖易变化的文本、数组下标或脆弱的 `nth-child` 选择器。
- 标注层使用 portal/顶层容器呈现，避免破坏原 DOM 布局。根据目标元素的 `getBoundingClientRect()` 定位，并在滚动、缩放、窗口尺寸变化、路由变化和动态 DOM 变化后重新计算。
- 对被弹窗、抽屉、下拉菜单等覆盖层中的控件，标注气泡应位于相同或更高的可见层级，同时避免截断和层级冲突。
- 多个目标拥挤时自动错位排列或提供紧凑模式，保持编号与目标的明确对应关系。
- 桌面端使用固定右侧栏；窄屏使用可收起的右侧抽屉。打开右侧栏不应永久压坏页面布局。
- 保留键盘操作：气泡可聚焦，Enter/Space 可打开；右侧条目可关闭和编辑；为气泡提供可读的 `aria-label`。
- 标注点击事件不能意外触发目标控件。关闭标注模式后，目标控件的原始点击、输入、选择、焦点和快捷键行为必须不变。

### 标签页隔离与事件规则

- 覆盖层容器和连接线默认使用 `pointer-events: none`；只有编号气泡、右侧栏和其内部按钮使用 `pointer-events: auto`。气泡尺寸要紧凑并避开标签文字中心，不能用透明大区域覆盖标签。
- 气泡事件只能在气泡自身边界内阻止传播，不能在 document、页面容器、标签栏或覆盖层根节点上全局拦截 `click`、`pointerdown`、`mousedown`、`touchstart` 或键盘事件。
- 不得通过阻止标签事件来打开标注。标签控件的点击、方向键、Enter/Space 及焦点行为必须继续交给原页面；标注气泡的点击与标签点击是两个独立命中区域。
- 识别项目实际的活动标签状态，优先读取组件状态、路由参数、`aria-selected="true"`、`data-state="active"` 或组件库的激活标识。不要假设 DOM 中最后一个、可见文字匹配项或固定下标就是当前标签。
- 标签页内的标注按 `page + scope/tabId` 过滤；页面标题、标签栏等共享元素使用公共 scope。每次切换只渲染“公共 scope + 当前活动标签 scope”，右侧栏也应用相同过滤。
- 切换标签时，关闭或暂存上一标签已打开的右侧详情，不允许它们继续混入当前标签列表。返回上一标签时可恢复该标签自己的打开状态，但不同标签的打开状态必须隔离。
- 许多组件库会把非活动标签内容保留在 DOM。渲染气泡前必须确认目标及其所有祖先真实可见：排除 `hidden`、`aria-hidden="true"`、`display:none`、`visibility:hidden/collapse`、无布局盒、非活动 tabpanel，以及被卸载或断开连接的元素。不能仅凭目标本身存在或 `getBoundingClientRect()` 有值就显示标注。
- 标签状态变化后，先更新活动 scope，再等待当前框架完成渲染或过渡，随后重新扫描可见目标和计算位置。使用项目状态订阅、路由订阅、MutationObserver 或 ResizeObserver 等合适机制；避免持续高频轮询。
- 对“系统配置”等多标签页面逐个标签建立独立标注集合。不同标签中语义不同的控件必须使用不同编号，即使它们处于相同屏幕坐标或复用同一组件模板。

## 编号和修改规则

- 使用全局连续编号 `A-001`、`A-002`……；一个控件对应一个编号，不因页面重新渲染而改变。
- 已有编号不可因排序、内容修改或新增控件而重排。新控件使用下一个未使用编号。
- 控件被移除时将记录标为“已废弃”，不复用该编号。控件迁移到其他组件但语义不变时保留编号并更新定位信息。
- 用户按编号提出修改时，更新对应记录和页面显示，保留编号。内容编辑必须经过现有数据持久化方式保存。
- 若项目已有标注数据，增量更新，不能覆盖用户之前的编辑。

## 检查与交付

实际运行页面并逐路由检查，不以静态代码扫描代替视觉验证。至少验证：

- 所有可见交互控件都有气泡且无重复编号；
- 气泡在滚动、缩放、响应式尺寸和动态渲染后仍指向正确目标；
- 点击多个气泡后，详情会同时出现在右侧栏，关闭单项和清空行为正确；
- 编辑内容、保存和刷新后的持久化正确；
- 标注开关、键盘操作以及原页面业务交互不受破坏；
- 页面跳转后加载正确页面的标注，不遗留上一页面的错误气泡。
- 用鼠标和键盘逐一切换每个标签，确认标签可切换、活动样式正确且原业务回调正常触发；
- 对每个标签分别截图或检查 DOM，确认只存在“页面公共标注 + 当前标签标注”，隐藏标签无气泡、无连接线、无右侧详情；
- 快速连续切换标签并在切换后滚动或缩放，确认没有旧标签气泡残留、重合或延迟回流。

完成后报告覆盖的页面数、控件数、编号范围、标注开关位置、数据保存位置、待确认项和实际验证结果。只有在项目无法运行时才退回代码级检查，并明确说明未完成视觉验证的原因。
